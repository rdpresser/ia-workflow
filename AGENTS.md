# AGENTS.md – AI Taskflow

## Project Overview

Study-focused Python PoC demonstrating async FastAPI, event-driven AI workflows, and modern quality tooling.
Architecture: `Client → FastAPI → SQLAlchemy/PostgreSQL → Pub/Sub → Async Worker → LangChain (OpenAI/Claude) → PostgreSQL`

## Key Source Files

| Path | Purpose |
|------|---------|
| `src/ai_taskflow/core/config.py` | Typed settings singleton (`settings`) — the only place to read config |
| `src/ai_taskflow/core/database.py` | Async engine, session factory, and `get_db_session` FastAPI dep |
| `src/ai_taskflow/models/task.py` | ORM entity + `TaskStatus` enum (PENDING → PROCESSING → COMPLETED/FAILED) |
| `src/ai_taskflow/schemas/task.py` | Pydantic DTOs: `TaskCreate` (inbound), `TaskResponse` (outbound) |
| `migrations/env.py` | Alembic env — **every new model must be imported here** to be autogenerated |
| `scripts/helper.sh` | Interactive menu for all common dev commands |

## Developer Workflows

```bash
# First-time setup after clone (idempotent)
./scripts/helper.sh   # choose option 11

# Or manually:
poetry install
poetry run pre-commit install --install-hooks

# Start infrastructure
docker compose up -d   # PostgreSQL + Redis

# Run Alembic migrations
poetry run alembic upgrade head

# Create a new migration after model changes
poetry run alembic revision --autogenerate -m "describe change"

# Run tests
poetry run pytest

# Lint + format
poetry run ruff check src/
poetry run ruff format src/

# Type-check (per file — see MyPy note below)
poetry run mypy src/ai_taskflow/core/config.py --explicit-package-bases

# Safe commit (add → pre-commit → add → commit)
./scripts/helper.sh   # choose option 8
```

> **MyPy quirk**: MyPy is disabled in the pre-commit hook due to a `src/`-layout namespace issue.
> Run it per-file with `--explicit-package-bases`, or use helper option `10` to check the whole codebase.

## Critical Patterns

### Settings — always use the singleton
```python
from src.ai_taskflow.core.config import settings
settings.db.async_url   # postgresql+asyncpg://...
settings.db.sync_url    # postgresql://... (Alembic only)
```
Config is split into `DatabaseSettings`, `SecuritySettings`, and `AISettings`, all
composed into the top-level `Settings`. Real env vars override `.env` file values.

### Database sessions — async only in application code
```python
# In FastAPI deps (api/deps.py pattern):
from src.ai_taskflow.core.database import get_db_session
async def endpoint(session: AsyncSession = Depends(get_db_session)): ...

# Never use psycopg2 or sync SQLAlchemy in FastAPI/worker code.
# psycopg2-binary is reserved for Alembic CLI migrations only.
```

### ORM models — inherit from `Base`, use `Mapped` columns
```python
from src.ai_taskflow.core.database import Base
class MyModel(Base):
    __tablename__ = "my_table"
    id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
```
All timestamps use `datetime.now(UTC)` — never `datetime.utcnow()`.

### Pydantic schemas — separate inbound/outbound DTOs
- `TaskCreate` (inbound POST body) extends `TaskBase`.
- `TaskResponse` (API output) uses `ConfigDict(from_attributes=True)` to parse ORM objects directly.
- Never expose ORM models directly from API endpoints.

### Adding a new model
1. Create `src/ai_taskflow/models/<name>.py` inheriting `Base`.
2. Import it in `migrations/env.py` (e.g., `from src.ai_taskflow.models.<name> import <Name>  # noqa: F401`).
3. Run `poetry run alembic revision --autogenerate -m "..."` then `poetry run alembic upgrade head`.

## Linting Rules (Ruff)

Line length: 100. Enabled rule sets: `E`, `F`, `I`, `B`, `C90`. Target: Python 3.14.
Run `poetry run ruff check src/` and `poetry run ruff format src/` before committing.

## Environment Variables

All read from `.env` (Docker Compose also reads it automatically):

| Variable | Used by |
|----------|---------|
| `POSTGRES_USER/PASSWORD/HOST/PORT/DB` | `DatabaseSettings` |
| `SECRET_KEY` | `SecuritySettings` (JWT) |
| `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` | `AISettings` — optional, `None` if unset |
| `REDIS_PORT` | Docker Compose redis service |

Infrastructure: `docker compose up -d` starts PostgreSQL 16 and Redis 7.
